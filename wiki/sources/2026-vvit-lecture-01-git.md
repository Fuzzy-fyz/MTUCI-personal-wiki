## Reliable extract

_Составлено LLM по тексту слайдов, не сверено человеком — отсюда `needs-review`._

- Система контроля версий хранит историю изменений файлов и позволяет управлять версиями проекта; Git — распределённая VCS, полная история лежит локально (слайды 6, 9).
- Git хранит не набор различий, а снимки состояния проекта (слайд 10).
- Git и GitHub — разные вещи: программа на компьютере и сервис для хранения репозиториев; Git работает независимо от GitHub (слайд 11). Есть и другие сервисы: GitLab, GitFlic, Bitbucket (слайд 12).
- Репозиторий — каталог проекта со служебной папкой `.git`, создаётся командой `git init` (слайды 13, 20).
- Три области: рабочий каталог → индекс (`git add`) → история (`git commit`); `git add` отбирает, `git commit` записывает — это два разных шага (слайды 14, 22, 23).
- Состояния файла: untracked, modified, staged, committed; их показывает `git status` (слайды 15, 21).
- Коммит — логически завершённое изменение с автором, временем, сообщением и ссылкой на предыдущий коммит (слайды 16, 23); хеш коммита и HEAD (слайды 17, 18).
- Ветка — указатель на коммит; `git branch`, `git switch`, `git merge`, конфликт слияния (слайды 26–29).
- Отмена: `git restore`, `git restore --staged`, `git revert`; `git reset --hard` опасен (слайды 30–32).
- Удалённый репозиторий: `git clone`, `git remote -v`, `git fetch` / `git pull` / `git push`, аутентификация токеном или SSH-ключом (слайды 33–37).
- `.gitignore` и то, что он не действует задним числом (слайды 38, 39).
- Правила командной разработки и ежедневный рабочий цикл (слайды 40–42).
